## Cenário de exemplo

Imagine que está desenvolvendo um sistema com uma entidade `Usuario`. Dois objetos `Usuario` devem ser considerados iguais **se tiverem o mesmo identificador único** (por exemplo, um ID ou e-mail), mesmo que sejam instâncias diferentes em memória.

### Por que sobrescrever `equals()`?

Se não sobrescrever `equals()`, a implementação padrão da classe `Object` compara referências de memória (`==`), o que é inadequado na maioria dos modelos de domínio.

Além disso, se utilizar coleções como `Set<Usuario>` ou `Map<Usuario, ...>`, a falta de uma implementação correta de `equals()` e `hashCode()` levará a comportamentos inesperados.

---

## Considerações essenciais ao sobrescrever `equals()`

Para manter a consistência e previsibilidade, o método `equals()` deve obedecer ao seguinte contrato:

1. Reflexivo -  `a.equals(a)` deve retornar `true`.
2. Simétrico - `a.equals(b)` ⇔ `b.equals(a)`.
3. Transitivo - Se `a.equals(b)` e `b.equals(c)`, então `a.equals(c)`.
4. Consistente - Chamadas múltiplas devem retornar o mesmo resultado.
5. Não-nullidade - `a.equals(null)` deve retornar `false`.

> Importante - Sempre que sobrescrever `equals()`, também sobrescrever `hashCode()` para manter o contrato:  
> Se dois objetos são iguais segundo `equals()`, então eles **devem** ter o mesmo valor de `hashCode()`.

---

## Exemplo de implementação

```java
import java.util.Objects;

public class Usuario {
    private final String id;
    private final String nome;
    private final String email;

    public Usuario(String id, String nome, String email) {
        this.id = id;
        this.nome = nome;
        this.email = email;
    }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (o == null || getClass() != o.getClass()) return false;

        Usuario usuario = (Usuario) o;
        return Objects.equals(id, usuario.id);
    }

    @Override
    public int hashCode() {
        return Objects.hash(id);
    }
}
